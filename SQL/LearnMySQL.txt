📌 Hiểu Sâu về Mô Hình Quan Hệ trong Cơ Sở Dữ Liệu

1️⃣ Các Loại Quan Hệ Trong Cơ Sở Dữ Liệu
    - Trong mô hình quan hệ, có 3 loại quan hệ chính giữa các bảng:
        - Quan hệ 1-1 (One-to-One)
        - Quan hệ 1-N (One-to-Many)
        - Quan hệ N-N (Many-to-Many)
    - Mình sẽ giải thích từng loại với ví dụ thực tế, cách nhận diện chúng trong bài toán, và cách triển khai trong SQL. 🚀

2️⃣ Quan Hệ 1-1 (One-to-One)
    🔹 Mô Tả
        - Một bản ghi trong bảng A chỉ liên kết với một bản ghi duy nhất trong bảng B, và ngược lại.
        - Dùng khi một thực thể có quá nhiều dữ liệu hoặc khi dữ liệu có mức độ bảo mật khác nhau.
    🔹 Ví Dụ Thực Tế
        - Mỗi sinh viên có một thông tin hồ sơ riêng (gồm số CCCD, địa chỉ chi tiết, hình ảnh).
        - Mỗi nhân viên có một tài khoản đăng nhập duy nhất.
    🔹 Cách Nhận Biết
        - Khi mỗi đối tượng chỉ có một phần dữ liệu tương ứng.
        - Nếu hai bảng có cùng một số lượng bản ghi tương ứng, có thể là quan hệ 1-1.
    🔹 Triển Khai Trong SQL
        Giả sử mỗi sinh viên có một hồ sơ riêng:
            CREATE TABLE SinhVien (
                MaSV INT PRIMARY KEY AUTO_INCREMENT,
                HoTen VARCHAR(50) NOT NULL
            );

            CREATE TABLE HoSoSinhVien (
                MaSV INT PRIMARY KEY,
                CCCD VARCHAR(12) UNIQUE,
                DiaChiChiTiet TEXT,
                HinhAnh VARCHAR(255),
                FOREIGN KEY (MaSV) REFERENCES SinhVien(MaSV) ON DELETE CASCADE
            );
        🔹 Giải thích:
            - MaSV là khóa chính của SinhVien, đồng thời cũng là khóa chính & khóa ngoại của HoSoSinhVien.
            - ON DELETE CASCADE: Khi xóa sinh viên trong SinhVien, hồ sơ của họ cũng bị xóa.
3️⃣ Quan Hệ 1-N (One-to-Many)
    🔹 Mô Tả
        - Một bản ghi trong bảng A có thể liên kết với nhiều bản ghi trong bảng B.
        - Ngược lại, mỗi bản ghi trong bảng B chỉ liên kết với một bản ghi trong bảng A.
    🔹 Ví Dụ Thực Tế
        - Một lớp có nhiều sinh viên, nhưng mỗi sinh viên chỉ thuộc một lớp.
        - Một nhân viên thuộc một phòng ban, nhưng một phòng ban có nhiều nhân viên.
    🔹 Cách Nhận Biết
        - Khi một thực thể A có nhiều thực thể B đi kèm.
        - Trong bảng B, có một cột chứa ID của bảng A làm khóa ngoại.
    🔹 Triển Khai Trong SQL
        - Quan hệ giữa sinh viên và lớp học:
            CREATE TABLE LopHoc (
                MaLop INT PRIMARY KEY AUTO_INCREMENT,
                TenLop VARCHAR(50) NOT NULL
            );

            CREATE TABLE SinhVien (
                MaSV INT PRIMARY KEY AUTO_INCREMENT,
                HoTen VARCHAR(50) NOT NULL,
                MaLop INT,
                FOREIGN KEY (MaLop) REFERENCES LopHoc(MaLop) ON DELETE SET NULL
            );
        🔹 Giải thích:
            - MaLop là khóa chính của LopHoc, đồng thời là khóa ngoại trong SinhVien.
            - ON DELETE SET NULL: Nếu lớp học bị xóa, MaLop trong SinhVien sẽ thành NULL.
4️⃣ Quan Hệ N-N (Many-to-Many)
    🔹 Mô Tả

1️⃣ Tối Ưu Hóa Truy Vấn SQL
    🔥 Vì Sao Cần Tối Ưu Hóa?
        - Trong thực tế, khi làm việc với hệ thống có hàng triệu bản ghi, nếu truy vấn không được tối ưu, tốc độ sẽ rất chậm, gây ảnh hưởng đến:
            - Trải nghiệm người dùng (website load chậm).
            - Tài nguyên hệ thống (CPU & RAM bị sử dụng quá nhiều).
            - Khả năng mở rộng (khó duy trì khi có nhiều dữ liệu).
    ⚡ 1.1. Dùng EXPLAIN Để Kiểm Tra Truy Vấn
        - MySQL cung cấp lệnh EXPLAIN để giúp bạn hiểu cách nó thực hiện truy vấn.
        📌 Ví dụ: Kiểm tra tốc độ truy vấn lấy danh sách sinh viên & lớp học
            EXPLAIN SELECT SinhVien.HoTen, LopHoc.TenLop
            FROM SinhVien
            JOIN LopHoc ON SinhVien.MaLop = LopHoc.MaLop;
        🔹 Khi nào nên dùng EXPLAIN?
            - Khi truy vấn chạy chậm.
            - Khi bạn muốn kiểm tra xem có thể tối ưu bằng INDEX hay không.
    ⚡ 1.2. Sử Dụng INDEX Để Tăng Tốc Độ Truy Vấn
        🔹 INDEX giúp MySQL tìm dữ liệu nhanh hơn, giống như mục lục của cuốn sách.

        📌 Ví dụ: Nếu bạn thường xuyên tìm kiếm theo HoTen, hãy tạo chỉ mục:
            CREATE INDEX idx_HoTen ON SinhVien(HoTen);
        📌 Ví dụ: Nếu hay tìm kiếm theo MaLop, hãy tạo chỉ mục:
            CREATE INDEX idx_MaLop ON SinhVien(MaLop);
        ✅ Lợi ích của INDEX:
            - Tăng tốc truy vấn SELECT khi sử dụng WHERE, JOIN, ORDER BY.
            - Cải thiện hiệu suất trên bảng lớn.
        ⚠️ Nhược điểm:
            - Tốn dung lượng: MySQL phải lưu INDEX riêng.
            - Làm chậm INSERT, UPDATE, DELETE vì MySQL phải cập nhật INDEX mỗi khi dữ liệu thay đổi.
        📌 Ứng dụng thực tế:
            - Hệ thống e-commerce có hàng triệu sản phẩm thường dùng INDEX trên ProductName, CategoryID, Price.
            - Hệ thống ngân hàng dùng INDEX trên AccountNumber, TransactionDate.
2️⃣ Câu Truy Vấn Con (SUBQUERY)
    ⚡ 2.1. SUBQUERY là gì?
        SUBQUERY là một truy vấn SQL nằm bên trong một truy vấn khác. Nó giúp bạn lấy dữ liệu phức tạp hơn mà không cần JOIN.

        📌 Ví dụ 1: Tìm sinh viên có điểm trung bình cao nhất
            SELECT HoTen, (SELECT AVG(Diem) FROM Diem WHERE Diem.MaSV = SinhVien.MaSV) AS DiemTrungBinh
            FROM SinhVien
            ORDER BY DiemTrungBinh DESC
            LIMIT 1;
        📌 Ví dụ 2: Tìm sinh viên học môn "Lập trình Python"
            SELECT HoTen FROM SinhVien
            WHERE MaSV IN (
                SELECT MaSV FROM Diem
                WHERE MaMon = (SELECT MaMon FROM MonHoc WHERE TenMon = 'Lập trình Python')
            );
        📌 Ứng dụng thực tế:
            - Tìm khách hàng có tổng số tiền mua hàng cao nhất.
            - Tìm nhân viên có lương cao nhất trong mỗi phòng ban.
        🔹 Khi nào dùng SUBQUERY?
            - Khi bạn chỉ cần một giá trị duy nhất (SELECT ... WHERE).
            - Khi không cần JOIN nhưng vẫn muốn lấy dữ liệu liên quan.
3️⃣ Giao Dịch (TRANSACTIONS)
    ⚡ 3.1. TRANSACTIONS là gì?
        TRANSACTIONS giúp đảm bảo toàn vẹn dữ liệu, nghĩa là:

        - Nếu có lỗi xảy ra giữa chừng, dữ liệu không bị lưu một phần.
        - Được dùng trong các hệ thống ngân hàng, thương mại điện tử, quản lý kho.
    📌 Ví dụ: Giao dịch ngân hàng - chuyển tiền
        START TRANSACTION;

        UPDATE TaiKhoan SET SoDu = SoDu - 500000 WHERE MaTK = 1;
        UPDATE TaiKhoan SET SoDu = SoDu + 500000 WHERE MaTK = 2;

        COMMIT;
    ✅ Nếu thành công, COMMIT sẽ lưu thay đổi.
    ❌ Nếu có lỗi, ta có thể ROLLBACK để hoàn tác.

    📌 Ví dụ: Nếu gặp lỗi
        START TRANSACTION;

        UPDATE TaiKhoan SET SoDu = SoDu - 500000 WHERE MaTK = 1;
        UPDATE TaiKhoan SET SoDu = SoDu + 'LỖI' WHERE MaTK = 2;  -- LỖI Ở ĐÂY!

        ROLLBACK;
    📌 Ứng dụng thực tế:

        - Khi đặt hàng online, nếu quá trình thanh toán bị lỗi, đơn hàng sẽ không bị ghi vào hệ thống.
        - Khi chuyển khoản ngân hàng, nếu có lỗi, số tiền sẽ không bị trừ một phần.
4️⃣ Stored Procedure - Viết Hàm SQL
    ⚡ 4.1. Stored Procedure là gì?
        - Stored Procedure là một hàm SQL có thể lưu trữ trong database, giúp: ✅ Tăng tốc độ xử lý (do đã được biên dịch trước).
            ✅ Tái sử dụng truy vấn.
            ✅ Giảm lỗi khi lập trình.

        📌 Ví dụ: Tạo hàm lấy danh sách sinh viên trong một lớp
            DELIMITER //
            CREATE PROCEDURE GetSinhVienByLop(IN ma_lop INT)
            BEGIN
                SELECT * FROM SinhVien WHERE MaLop = ma_lop;
            END //
            DELIMITER ;
        📌 Gọi hàm:
            CALL GetSinhVienByLop(1);
        📌 Ví dụ: Tạo Stored Procedure tính điểm trung bình
            DELIMITER //
            CREATE PROCEDURE GetDiemTrungBinh(IN ma_sv INT)
            BEGIN
                SELECT AVG(Diem) AS DiemTrungBinh FROM Diem WHERE MaSV = ma_sv;
            END //
            DELIMITER ;
        📌 Gọi hàm:
            CALL GetDiemTrungBinh(1);

        📌 Ứng dụng thực tế:

            - Hệ thống bán hàng có thể có Stored Procedure để tính tổng doanh thu.
            - Hệ thống nhà hàng có Stored Procedure để kiểm tra lượng nguyên liệu tồn kho.
