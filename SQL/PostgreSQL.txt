Cú pháp định nghĩa quan hệ giữa các bảng trong MySQL và PostgreSQL có khá nhiều điểm tương đồng, nhưng cũng có những sự khác biệt nhỏ. Dưới đây là so sánh về cách định nghĩa các quan hệ như khóa chính (Primary Key), khóa ngoại (Foreign Key) và ràng buộc (Constraints) trong cả hai hệ quản trị cơ sở dữ liệu.

1. Khóa chính (Primary Key)
Khóa chính là một ràng buộc được sử dụng để xác định một trường hoặc tập hợp các trường duy nhất trong bảng. Cả MySQL và PostgreSQL đều hỗ trợ cú pháp tương tự.

MySQL:

CREATE TABLE employees (
    id INT AUTO_INCREMENT,
    name VARCHAR(100),
    PRIMARY KEY (id)
);
PostgreSQL:

CREATE TABLE employees (
    id SERIAL,
    name VARCHAR(100),
    PRIMARY KEY (id)
);
2. Khóa ngoại (Foreign Key)
Khóa ngoại được sử dụng để thiết lập mối quan hệ giữa hai bảng, đảm bảo rằng một giá trị trong bảng con phải tồn tại trong bảng cha.

MySQL:

CREATE TABLE orders (
    order_id INT AUTO_INCREMENT,
    customer_id INT,
    PRIMARY KEY (order_id),
    FOREIGN KEY (customer_id) REFERENCES customers(id)
);
PostgreSQL:

CREATE TABLE orders (
    order_id SERIAL,
    customer_id INT,
    PRIMARY KEY (order_id),
    FOREIGN KEY (customer_id) REFERENCES customers(id)
);
3. Ràng buộc (Constraints)
Các ràng buộc như NOT NULL, UNIQUE, CHECK, và DEFAULT được hỗ trợ trong cả MySQL và PostgreSQL, nhưng PostgreSQL cung cấp khả năng xử lý các ràng buộc phức tạp hơn.

MySQL:

CREATE TABLE products (
    product_id INT AUTO_INCREMENT,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(10, 2) CHECK (price > 0),
    PRIMARY KEY (product_id)
);
Lưu ý: Trong MySQL, ràng buộc CHECK không được xử lý mạnh mẽ như trong PostgreSQL. MySQL chỉ kiểm tra các điều kiện này trong các phiên bản mới hơn, nhưng không đảm bảo tính toàn vẹn dữ liệu như trong PostgreSQL.

PostgreSQL:

CREATE TABLE products (
    product_id SERIAL,
    name VARCHAR(100) NOT NULL,
    price DECIMAL(10, 2) CHECK (price > 0),
    PRIMARY KEY (product_id)
);
4. Ràng buộc Khóa Ngoại với Các Tùy Chọn (ON DELETE, ON UPDATE)
Cả MySQL và PostgreSQL đều hỗ trợ các hành động như ON DELETE CASCADE, ON UPDATE CASCADE, ON DELETE SET NULL, và ON DELETE RESTRICT khi thiết lập khóa ngoại.

MySQL:

CREATE TABLE orders (
    order_id INT AUTO_INCREMENT,
    customer_id INT,
    PRIMARY KEY (order_id),
    FOREIGN KEY (customer_id) 
        REFERENCES customers(id)
        ON DELETE CASCADE
);
PostgreSQL:

CREATE TABLE orders (
    order_id SERIAL,
    customer_id INT,
    PRIMARY KEY (order_id),
    FOREIGN KEY (customer_id) 
        REFERENCES customers(id)
        ON DELETE CASCADE
);
5. Unique Constraints
Ràng buộc duy nhất (UNIQUE) được sử dụng để đảm bảo rằng tất cả các giá trị trong một cột hoặc nhóm các cột là duy nhất.

MySQL:

CREATE TABLE employees (
    id INT AUTO_INCREMENT,
    email VARCHAR(100) UNIQUE,
    PRIMARY KEY (id)
);
PostgreSQL:

CREATE TABLE employees (
    id SERIAL,
    email VARCHAR(100) UNIQUE,
    PRIMARY KEY (id)
);
6. Tạo mối quan hệ nhiều-một (One-to-Many)
Cả MySQL và PostgreSQL đều sử dụng khóa ngoại để xác định mối quan hệ một-nhiều (One-to-Many), nơi bảng con (child table) có khóa ngoại tham chiếu đến khóa chính của bảng cha (parent table).

MySQL:

CREATE TABLE authors (
    author_id INT AUTO_INCREMENT,
    name VARCHAR(100),
    PRIMARY KEY (author_id)
);

CREATE TABLE books (
    book_id INT AUTO_INCREMENT,
    title VARCHAR(100),
    author_id INT,
    PRIMARY KEY (book_id),
    FOREIGN KEY (author_id) REFERENCES authors(author_id)
);
PostgreSQL:

CREATE TABLE authors (
    author_id SERIAL,
    name VARCHAR(100),
    PRIMARY KEY (author_id)
);

CREATE TABLE books (
    book_id SERIAL,
    title VARCHAR(100),
    author_id INT,
    PRIMARY KEY (book_id),
    FOREIGN KEY (author_id) REFERENCES authors(author_id)
);
7. Mối quan hệ Nhiều-nhiều (Many-to-Many)
Mối quan hệ nhiều-nhiều thường được thực hiện qua một bảng giao liên (junction table), chứa các khóa ngoại tham chiếu đến cả hai bảng.

MySQL:

CREATE TABLE students (
    student_id INT AUTO_INCREMENT,
    name VARCHAR(100),
    PRIMARY KEY (student_id)
);

CREATE TABLE courses (
    course_id INT AUTO_INCREMENT,
    course_name VARCHAR(100),
    PRIMARY KEY (course_id)
);

CREATE TABLE student_courses (
    student_id INT,
    course_id INT,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (course_id) REFERENCES courses(course_id)
);
PostgreSQL:

CREATE TABLE students (
    student_id SERIAL,
    name VARCHAR(100),
    PRIMARY KEY (student_id)
);

CREATE TABLE courses (
    course_id SERIAL,
    course_name VARCHAR(100),
    PRIMARY KEY (course_id)
);

CREATE TABLE student_courses (
    student_id INT,
    course_id INT,
    PRIMARY KEY (student_id, course_id),
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (course_id) REFERENCES courses(course_id)
);
Tổng kết
Cả MySQL và PostgreSQL đều cung cấp cú pháp tương tự khi định nghĩa quan hệ giữa các bảng, 
nhưng PostgreSQL có xu hướng hỗ trợ các tính năng mạnh mẽ và linh hoạt hơn, đặc biệt khi làm 
việc với các ràng buộc và dữ liệu phức tạp. PostgreSQL cũng tuân thủ chuẩn SQL nghiêm ngặt hơn MySQL, 
với các tính năng bổ sung như CHECK ràng buộc mạnh mẽ và hỗ trợ các kiểu dữ liệu phức tạp.
