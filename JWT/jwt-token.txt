jwt token viết tắt của json web token, có nghĩa đây là 1 token nó lưu được dữ liệu và nó sử dụng json để nó lưu
jwt token nó có 3 thành phần, ngăn cách bằng dấu chấm, thế nên có 2 dấu chấm, thành phần thứ nhất gọi là
- header: nó sẽ lưu các thông tin như là thuật toán mã hóa(alg), kiểu token(typ)
- payload: nó sẽ lưu các thông tin như là chủ thể(sub), thường là lưu cái userId để định danh cái ông đang đăng nhập bằng các token đấu là ông nào. ngoài ra các bạn thích lưu cái gì thêm thì
các bạn lưu, nhưng thường thì chúng ta hạn chế làm điều đó bởi vì nó tăng cái dung lượng token
- signature: nghĩa là chữ ký, cái cách để tạo ra chữ ký sẽ mã hóa base64, của một cái chữ ký được sủ dụng hmacsha256 để mã hóa, nó sẽ dựa vào dữ liệu của header nối bằng dấu chấm 
với cái dữ liệu của payload cộng với 1 cái secret key là một cái mã bí mật để nó tạo ra cái chữ ký.

thì bây giờ các bạn hãy tưởng tượng, cái header, payload nó giống như việc các bạn gửi dữ liệu bằng cách là các bạn gửi thư ấy,
header là những cái thông tin râu ria, những cái thông tin mang tính mô tả đường đi nước bước thì nó sẽ là cái thông tin ngoài phong bì.
còn payload nó là cái ruột bên trong phong bì, nó chứa dữ liệu chính.
chữ ký thì ngoài đời các bạn ký để làm gì, để chống giả mạo đúng không, để xác thực đúng không. đấy, thì cái này nó cũng vậy thôi

thì đầu tiên các bạn nhìn thấy nó giải quyết vấn đề là không lưu dữ liệu ở trên máy chủ, bởi vì các bạn thấy nó lưu ở payload, thì đến lúc 
cái token nó được gửi lên trên server ấy thì server nó sẽ đọc cái token để nó lấy ra được cái userId và nó sẽ query vào db để nó láy ra người
dùng thôi chứ nó không cần phải ánh xạ từ sessionId tới session data nữa đúng không, nên là nó sẽ giải quyết được vấn đề này luôn
